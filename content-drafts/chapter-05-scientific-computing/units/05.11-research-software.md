## 5.11.1 Git and collaboration hygiene

Core workflow: `status`, `add`, `commit`, `push`, `branch`, `merge`. Commit messages explain *why*.

**Never commit:** bulk `data/raw`, `.env`, API keys, large intermediates.

`.gitignore` should cover virtualenvs, caches, OS junk, secrets.

Tag releases that match paper or report submissions.

## 5.11.2 Environments and licensing

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
Record Python version. Prefer lockfiles as projects grow.

**Licences.** Choose an OSI licence for code when appropriate; data licences are separate. Add `CITATION.cff`. Cite libraries that enable the work (Wilson et al. 2017 principles).

**Containers.** Docker when collaborator environments diverge—not mandatory for every homework-scale analysis (Unit 5.12 / Subject 11).

## 5.11.3 Modular structure

```
src/package_name/
  __init__.py
  io.py
  preprocess.py
  models.py
  plots.py
configs/default.yaml
tests/
scripts/run_analysis.py
README.md
```

Configuration files beat hardcoded paths. Logging beats print. CLI entry (`argparse` / `typer`) beats “edit cell 3.”

**Example CLI skeleton**
```python
# scripts/run_analysis.py
def main(config_path: str) -> None:
    """Load config, run pipeline stages, write outputs and manifest."""
    ...

if __name__ == "__main__":
    import argparse
    p = argparse.ArgumentParser()
    p.add_argument("--config", default="configs/default.yaml")
    args = p.parse_args()
    main(args.config)
```

## 5.11.4 Testing and validation

### What to test
Unit conversions, mask logic, date aggregations, output schema, regression against small golden fixtures.

### pytest pattern
```python
import numpy as np
from package.preprocess import celsius_to_kelvin

def test_celsius_to_kelvin_freezing():
    assert np.isclose(celsius_to_kelvin(0.0), 273.15)

def test_celsius_to_kelvin_roundtrip():
    t = 32.5
    assert np.isclose(celsius_to_kelvin(t) - 273.15, t)
```

### Data validation
Range checks, allowed categories, CRS presence, monotonic time index—custom asserts or libraries such as `pandera`.

### CI
Minimal GitHub Actions workflow running `pytest` on push. Start small.

### Determinism
RNG seeds; avoid unsorted dict iteration affecting outputs; record library versions in the environment file.

## 5.11.5 Documentation and the software gate

README must include: purpose, data access, environment setup, **one-command rerun**, known limitations.

Docstrings for public functions. Architecture notes for non-obvious decisions.

**Definition of done (software gate)**
- [ ] Modules importable; no reliance on notebook cell order  
- [ ] ≥3 meaningful tests passing  
- [ ] Pinned dependencies  
- [ ] Data manifest for inputs  
- [ ] README with one-command (or clearly numbered) reproduce steps  
- [ ] No secrets in history  

---

## Failure modes (curriculum-mandated)
Notebook-only hidden state; unpinned environments; credentials in git; untested scale-factor/timezone code; “it runs on my laptop” without instructions.

## Exercises
**A:** Write two tests for a unit-conversion function; add a failing test then fix.  
**B:** Convert a messy analysis notebook into package + `run_analysis.py` + tests.  
**C:** Peer-reproduce a classmate’s repo from README alone; file issues for blockers.

## Deliverable
Repository meeting the software gate above.
