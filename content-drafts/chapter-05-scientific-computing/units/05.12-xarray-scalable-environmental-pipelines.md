## Purpose

Environmental data are commonly multidimensional: time × latitude × longitude, with additional dimensions for depth, ensemble member, band, scenario or sensor. Treating these datasets as ordinary flat tables can obscure coordinate meaning, units, chunking costs and alignment errors. This unit develops a defensible workflow for labeled arrays and scalable pipelines using xarray and its surrounding ecosystem. The aim is not simply to make a dataset fit in memory; it is to preserve scientific meaning while managing I/O, coordinate alignment, computation and validation.

## Learning outcomes

Learners will be able to:

1. Inspect an xarray Dataset/DataArray and interpret dimensions, coordinates, variables, attributes, units and encodings.
2. Select, align, resample, reproject or combine arrays while making spatial and temporal support explicit.
3. Design chunking and lazy computation strategies that match the operation and available memory.
4. Build validated pipelines for quality control, missingness, aggregation and derived environmental features.
5. Compare eager and chunked outputs, record performance/provenance, and explain limitations of scalable processing.

## Lesson 5.12.1 — Labeled arrays and multidimensional data models

A DataArray represents values with named dimensions, coordinates and attributes; a Dataset groups related variables that share dimensions or coordinates. Inspect shapes, coordinate values, units, calendar/time encoding, CRS metadata and missing-value conventions before analysis. Dimension names are not sufficient evidence that two arrays share the same grid or temporal support.

**Practice:** Open a small gridded environmental dataset and produce a data inventory: variables, dimensions, coordinates, units, time frequency, spatial grid, missingness and source provenance.

## Lesson 5.12.2 — Coordinate alignment, selection and aggregation

xarray operations often align by coordinate labels rather than positional index. This can prevent some silent index errors, but it can also introduce missing values or unexpectedly intersect coordinates. Inspect alignment explicitly before arithmetic or merging. Distinguish point selection, nearest-neighbour selection, spatial masking, temporal resampling, interpolation and reprojection: these operations answer different questions and have different scientific assumptions.

For climate series, specify time zone/calendar, sampling frequency, aggregation window and baseline. For rasters, check CRS, grid transform, resolution, cell alignment and spatial extent. Reprojection or interpolation should not be treated as a metadata-only change.

**Practice:** Align two synthetic time–space arrays with a deliberate missing coordinate, explain the resulting values, and choose a documented strategy for handling the mismatch.

## Lesson 5.12.3 — Lazy computation, chunking and Dask

Dask-backed arrays can defer computation and divide work into tasks, but chunking is an algorithmic design choice. Chunks that are too small add scheduler overhead; chunks that are too large can exceed memory. Operations that require global reductions, rechunking or shuffling may be costly. Choose chunks based on the access pattern and operation, inspect task graphs when useful, and compute only bounded outputs when exploring.

Lazy execution does not guarantee faster processing. Benchmark representative operations, track memory and I/O, and avoid repeated computation of the same expensive intermediate result.

**Practice:** Compare an eager NumPy/xarray calculation with a Dask-backed equivalent on synthetic data. Check numerical agreement within a justified tolerance, measure elapsed time and document chunk sizes, scheduler and hardware limits.

## Lesson 5.12.4 — Robust spatiotemporal feature pipelines

A robust pipeline separates source discovery, ingestion, validation, transformations, feature calculation, aggregation and export. For each derived variable, record its formula, units, spatial/temporal support and missing-data behaviour. Examples include seasonal anomalies, rolling summaries, zonal statistics and derived heat or vegetation features. Keep a stable time coordinate and preserve source metadata through transformations.

Do not combine arrays just because dimension labels match. Verify units, CRS/grid alignment, calendar, temporal support and variable semantics. If the pipeline uses raster reprojection, resampling or area weighting, state the method and why it fits the analysis.

**Practice:** Build a synthetic time × y × x pipeline that validates coordinates, computes a seasonal anomaly and regional mean, and writes a compact output with source/method metadata. Include an explicit check for unexpected missingness and coordinate drift.

## Lesson 5.12.5 — Validation, performance and reproducible outputs

Validate both scientific content and execution behaviour. Check dimensions, coordinate monotonicity/uniqueness, units, valid ranges, expected missingness, aggregation consistency and output schema. Compare eager and lazy results on a bounded fixture. Performance reports should state data size, chunks, hardware/environment, wall time and peak memory when available; results from one machine are not universal.

Use safe, documented output formats and preserve metadata that consumers need. A pipeline is not validated merely because it completed without an exception. Record failed checks and known limitations rather than silently accepting suspect outputs.

**Practice:** Create a release checklist and a small validation report for the pipeline. Include numerical agreement, coordinate integrity, missingness, data provenance, environment and performance evidence.
