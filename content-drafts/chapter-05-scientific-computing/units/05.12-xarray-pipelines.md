## 5.12.1 xarray fundamentals

### 5.12.1.1 DataArray and Dataset
Labelled dimensions (`time`, `lat`, `lon`); coordinates; attributes for units and CF-style metadata.

### 5.12.1.2 Selection and computation
`sel`, `isel`, `groupby`, `resample`, `rolling`, `weighted` means (cosine latitude). Always check that coordinate alignment is intentional.

### 5.12.1.3 Calendars and units
Model calendars (360-day) and accumulation conventions differ. Convert temperatures deliberately (Unit 5.1). Decode encodings with `decode_cf` awareness.

### 5.12.1.4 Lazy evaluation and chunks
Dask integration for larger-than-memory arrays. Chunk shape affects performance; profile before scaling.

**Illustrative pattern**
```python
import numpy as np
import xarray as xr

ds = xr.open_dataset("era5_t2m.nc")  # path illustrative
t2m_c = ds["t2m"] - 273.15
monthly = t2m_c.resample(time="MS").mean()
weights = np.cos(np.deg2rad(ds.lat))
weighted = t2m_c.weighted(weights).mean(("lat", "lon"))
```
*Illustrative — variable names depend on the file; run locally after checking metadata.*

## 5.12.2 Reliable pipelines

### 5.12.2.1 Stage contract
Each stage declares: inputs, outputs, parameters, validation checks, log location. Write to a temporary path → validate → atomic move into place.

### 5.12.2.2 Checksums and provenance
Hash inputs and outputs; store in the manifest. Record code git SHA and config hash alongside data version.

### 5.12.2.3 Failure handling
Retries for transient downloads; never mark a partial file complete. Alert on schema drift.

### 5.12.2.4 Orchestration options
Makefile or shell for small graphs; Snakemake/Prefect/Airflow when complexity justifies them—not fashion.

## 5.12.3 Scale, versioning, archive

### 5.12.3.1 Laptop vs cloud vs HPC
Criteria: data volume, CPU/GPU need, cost, licence, **exit strategy** (keep intermediates in open formats).

### 5.12.3.2 Versioning
Hashed directories or DVC-style tracking; model/data version in every figure caption for ML outputs (Subjects 6/12).

### 5.12.3.3 Research snapshots
Archive code + config + manifests (Zenodo/OSF-style) at submission time; DOIs when appropriate.

## Failure modes
Silent coordinate misalignment; ignoring calendar/accumulation docs; non-idempotent “append” stages; cloud lock-in without export plan; pipelines without tests on unit conversions.
